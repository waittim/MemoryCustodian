# Controlled development pilot plan — 2026-11-13

This plan fixes the formal pilot settings before its result collection. A
separate single-task preflight verifies runtime availability and is excluded
from the formal matrix. This is development-set evidence, not a claim-bearing
or held-out experiment. No task, fixture, oracle, or reference solution will be
tuned in response to pilot outcomes.

- Suite: `core`, split `pilot-development`, all 18 task version 1 definitions.
- Repositories: the two content-hash-pinned fixtures, `field-ledger` and
  `route-notes`; existing fixture and task hashes remain unchanged.
- Conditions: `NO_MEMORY`, `PLATFORM_FILE_ONLY`, `EQUIVALENT_MANUAL_DOCS`,
  `MEMORYCUSTODIAN`.
- Runtime: real Codex CLI `exec --json`, model `gpt-6.1-sol`, reasoning `low`.
- Repetitions: one independent, ephemeral session per task and condition;
  72 formal sessions. No resume of agent conversations and no outcome-based
  retries. Infrastructure blockers remain visible in the records.
- Budget: 180 seconds per agent invocation; no explicit token cap. Four
  concurrent sessions; condition order rotates by sorted task index.
- Permissions: `workspace-write`, agent shell network access disabled,
  approval policy `never` (restricted actions fail rather than escalate).
  User config, plugins, host skill discovery, external memories, web search,
  and agent delegation are disabled for the subprocess sessions. Runtime
  authentication uses the existing local login without copying credentials.
- Isolation: fresh temporary checkouts outside this repository. Only the
  condition's visible sources are copied; hidden graders, reference solutions,
  other task overlays, prior results, and the harness are absent. The same
  neutral prompt prefix is used in every condition. This is controlled fixture
  isolation plus sandbox/prompt confinement, not an adversarial read jail.
- Grading: run visible tests and the existing mechanical hidden oracle after
  the agent exits. A run passes only when both pass. Preserve every outcome;
  report missing/infrastructure results separately from task failures.
- Primary outcome: paired `task_success` for `EQUIVALENT_MANUAL_DOCS` versus
  `MEMORYCUSTODIAN`, with task as analysis unit. Report all 18 pairs, discordant
  counts, percentage-point difference, and the runner's deterministic paired
  task bootstrap interval (10,000 samples, seed 0).
- Interpretation: small, purpose-built, previously available development
  tasks; one repetition cannot establish general effectiveness or runtime
  variability. An empirical bootstrap interval can collapse when every pair
  has the same difference; that is not evidence of population equivalence.
  Results and timing/token observations are descriptive, not causal or
  latency claims. The smallest meaningful effect remains unset because this
  is not a claim-bearing sample.
- Evidence: append-only normalized records include task, prompt, input tree,
  fixture, implementation, runtime, event-stream hashes and observed usage.
  Normalized action traces retain tool types, exit statuses and source-path
  mentions without raw command output, reasoning, prompts, or machine paths.
  Unobserved routing/context-token/read-count metrics stay `null`.
- Acceptance: 72 normalized real-runtime records, exactly one for each cell,
  no infrastructure blockers; failures are valid experimental outcomes.
  Reproduction instructions and the release checklist will link the records
  and report. Production protocol remains 0.8 / Entry schema 3.

The held-out expansion remains a separate plan: at least 36 paired tasks
across three pinned repositories, with tasks kept out of harness tuning and
the meaningful-effect threshold fixed before claim-bearing collection.

## Reproduction

Use a logged-in Codex CLI supporting the listed isolation flags, Python
3.10 or newer, and a fresh record directory/repetition ID. The recorded CLI
version is authoritative for this pilot; a rerun is a new sample, not a way
to overwrite these outcomes.

```bash
python3.13 scripts/run-memory-bench.py --check-integrity
python3.13 scripts/run-batch-benchmark.py \
  --mode live --runtime codex --codex-executable codex \
  --model-version gpt-6.1-sol --timeout 180 --jobs 4 \
  --condition-order balanced --repetition-id pilot-20261113 \
  --record-dir docs/evaluations/benchmark/runs/pilot-2026-11-13 \
  --report-file docs/evaluations/benchmark/RESULTS.md
```

Codex automation follows [official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode)
and [per-invocation configuration](https://learn.chatgpt.com/docs/config-file/config-reference).
